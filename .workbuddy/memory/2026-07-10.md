## curl 全接口自测（后端自启 + 从登录开始）

### 结论
- **所有接口代码功能正常**。登录/匿名/用户鉴权/管理员鉴权/写操作/鉴权失败分支全部符合预期。
- 唯二失败：`GET /user/category/list` 与 `GET /admin/dashboard/today`，**纯环境问题，非代码 bug**，已用堆栈证明。

### 根因：Windows ↔ WSL 网络互相掣肘
Redis 在 WSL、MySQL 在 Windows，NAT 模式 + 本机代理(127.0.0.1:7892) 导致 WSL2 localhost 端口转发失效。
- 后端跑在 Windows：MySQL(localhost) 通、curl 通，但连不上 WSL 的 Redis → `RedisConnectionFailureException: Unable to connect to 127.0.0.1:6379`（CategoryServiceImpl.java:129 / StatisticsServiceImpl.java:72 的缓存 .get()）。
- 后端跑在 WSL：Redis(127.0.0.1) 通，但 MySQL 报 `Access denied for user 'root'@'172.24.25.52'`（Windows MySQL 只授权 root@localhost），且 Windows 侧 curl 不到 WSL 的 8080（Windows→WSL 任意端口 TCP 被拒，仅 ICMP ping 通）。
- WSL 网关(Windows host) = 172.24.16.1；WSL eth0 IP = 172.24.25.52；Redis 绑定 0.0.0.0:6379，WSL 内部 ping=PONG。

### 彻底修复方案（用户本次选择"不打通只给结论"，未执行）
1. **推荐**：`.wslconfig` 加 `networkingMode=mirrored` + `wsl --shutdown` 重启 → Windows/WSL 共享 localhost，后端留 Windows，MySQL+Redis 全通。
2. 备选：给 Windows MySQL 加 `root@'%'` 授权，后端跑 WSL 内、测试也在 WSL 内完成。

### 保留的代码改进
- `media-web/.../config/GlobalExceptionHandler.java`：catch-all 的 `@ExceptionHandler(Exception.class)` 之前只返回"系统异常"不打日志，吞掉了所有真实堆栈。已加 SLF4J logger + `log.error("未捕获的系统异常", e)`。这是永久改进，本次排障全靠它。
